# shosoin

> 「その仕様、CLAUDE.md に書いといて」
> 「README にも書いておきますね」
> 「docs/ にも同じ説明があった気がする」
> 「三箇所とも、微妙に違うことが書いてありますが」
> 「……どれが本当？」

三冊の本に三通りの真実が書いてある書庫を、人は書庫と呼びません。呼ぶとしたら、物置です。`shosoin` は、その物置を、千三百年物が残る蔵に変えるプラグインです。

名前は正倉院から取りました。奈良に実在する宝庫で、八世紀の紙も布もガラスも、朽ちずに今も残っています。秘訣は魔法ではなく、運用です。扉は勅封で、開けるには許しが要る。年に一度は宝物を取り出して風を通し、状態を検める。残すことを構造と習慣にした蔵だけが、千年後も蔵であり続けます。

## これは何？

プロジェクトの書かれた知識を、それぞれ性質の違う五つの棚と一枚の案内板に配架し、収めた宝物がいまも真実かを検める蔵です。

- **CLAUDE.md** は蔵の憲章です。価値観と判断基準だけを、常時ロードの代価を毎回払う場所として英語で書きます。ここは蔵で最も入りにくい棚です。他のすべての棚に断られた知識だけが入居を申請でき、そこから複数のルールを導ける文だけが審査を通ります。そのまま守れて機械的に検査できる文はルールなので、規約として docs/ 行きです
- **docs/** は現在の目録です。「今この瞬間に何があるか」と「いま守るべき規約」を書きます。構成、手順、データコントラクト、慣例。読むのはコードを書く前で、書いた後の言い訳のためではありません
- **adr/** は決定の書庫です。「なぜそう決めたか、何を捨てたか」を時系列で綴じます。一度採用された記録は書き換えず、判断が変わったら新しい一枚で上書きではなく置き換えます。すべての決定が不変の記録として時系列に刻まれていく様は、世界の全記憶が記されるというアカシックレコードに少し似ています。ただしこちらは実在して、grep が効きます。書庫はルート直下に建ちます。決定の記録は現状説明の押し入れに仕舞う物ではないからです
- **references/** は標本室です。スプレッドシートのサンプル行、捕獲したAPIレスポンス。散文にせず、加工せず、コードからも読み込まない生データの棚です
- **notes/** は作業台です。タスクの間だけ物を広げる場所で、作業メモ、レビューの控え、試作品、引き継ぎ書が載ります。タスクが閉じるとき台の上は検分され、残す価値のある発見は正規の棚へ昇格し、残りは片付けられます。台の上に居座った物は、信頼の対象から外れます。消える定めの場所なので、恒久の棚から作業台へリンクを張ることはありません
- **README.md** は門前の案内板です。初めて来た人に、ここが何の蔵で、どの棚に何があるかを示します

配架の原則はただ一つ、**一つの事実に、住所は一つ**。同じ内容が二つの棚にあると、現実が動いたときにどちらか一方だけが更新され、読者はもうどちらも信じられなくなります。腐った文書は、信頼されているぶん、無い文書より悪いのです。

## 特徴

- **配架には必ず証拠を添えます**: 「このファイルのこの節は、複数のルールを導く価値観ではなく今日の手順なので、docs/ 行きです」。ファイル名の雰囲気で宝物を動かす蔵守は、蔵守ではなく引っ越し業者です
- **憲章は最後の関門です**: 分類の質問は作業台から始まり、憲章で終わります。最初に憲章を聞く蔵は、価値観っぽい文を片端から憲章に吸い込んで肥大します。この蔵では、他の全部の棚に断られてから、ようやく憲章の審査が始まります
- **曝涼が中身の嘘を暴きます**: 正倉院が年に一度宝物に風を通して検めるように、点検は各文書の主張をディスク上の現実と突き合わせ、「ページは X と言うが、リポジトリは Y を示す」の形で報告します。採用後にこっそり書き換えられた ADR も、タスクが終わったのに居座っている作業メモも、git の履歴が覚えています
- **訳語の腐敗も発見です**: 日本語で書かれた文書に直訳の専門用語が混じっていたら、曝涼が普通の言い方への置換案つきで報告します。最初の記録に植わった訳語は後続のすべての文書が文体見本として写し、ずれが複利で進むからです。だから建立も、引き渡しの前に自分の書いた文書を同じ基準で校正し、リンク・索引・フックの機械的検査を済ませてから鍵を渡します
- **守れないことを、守らせません**: 憲章に書いても破られうることのうち、設定とフックで不可能にできるものは、文書でなく機械に持たせます。プロジェクトの `.claude/` に三つの保証を設置します。私的メモリの閉鎖は三段構えで、公式設定で機能を切り、フックで書き込みの試みを止め、セッション開始のたびに過去の私物を掃除します。誰にも見えない場所に書かれた知識は、記録ではなく隠匿だからです。アトリビューションの設定は、コミットとプルリクエストに自動で付く生成物の署名を根元で止めます。絵文字のフックは、どのファイルへの書き込みであれ絵文字を含むものを拒みます。思想の代わりに飾りが置かれた文章は、人が書いたものとして読まれないからです。更地には setup が設置し、既存の蔵では audit が保証の欠如を発見として報告して、承認のうえ設置します。保証はプロジェクトの持ち物になるので、shosoin を無効にしても効き続けます
- **扉は勅封です**: 監査も点検も、まず報告を差し出し、あなたが頷いた分だけ蔵に手を入れます。移動は `git mv` で履歴ごと運び、リンクと索引も同じ一手で追随させます。リンク切れを残す移動は、移動ではなく遺失です
- **綺麗な蔵には綺麗と言います**: 違反ゼロの監査報告も、全書合格の点検報告も、空振りではなく成果です。仕事を見せるために問題を発明したりはしません
- **空の棚は作りません**: 生データの無いプロジェクトに references/ は建てませんし、notes/ は最初のタスクが何かを残すまで生まれません。空の標本室は家具ではなく、ただの埃です

## コンポーネント

| 種別 | 名前 | 説明 |
|------|------|------|
| Command | `/shosoin:audit` | 全文書を棚に振り分け、配架違反を証拠つきで報告。承認された配架案だけを実行する |
| Command | `/shosoin:inspect` | 曝涼。各文書の主張を現実と突き合わせ、古びた記述・切れたリンク・書き換えられた記録・居座った作業メモ・直訳の専門用語を報告する |
| Command | `/shosoin:setup` | 文書構造の無いプロジェクトに、棚と案内板を実際の観察に基づいて建立し、私的メモリの閉鎖・アトリビューション・絵文字の三つの保証を設置する |
| Skill | `shelving-contract` | 配架ルール・配架手順・点検手順・テンプレート・憲法の種。「この情報どこに書く?」に随時答える |

## 使い方

散らかった蔵には監査を。

```
/shosoin:audit
```

中身が信じられなくなったら曝涼を。

```
/shosoin:inspect
```

更地には建立を。

```
/shosoin:setup
```

会話の途中で「これって docs/ と README どっちに書くべき?」と聞くだけでも、スキルがルールから答えます。コマンドの儀式は要りません。

## setup が最初にやる、少し行儀のいいこと

建立のとき、蔵は最初の二枚の決定記録を自分で書きます。「ADR を使うという決定」と「配架ルールを採用するという決定」です。日付は建立した当日、却下した代替案も正直に記します。「決定を記録せよ」と説く構造が自分の誕生の記録を持っていなかったら、その蔵は落成の日から自己矛盾で軋むからです。

もう一つ。憲章を持たないプロジェクトには、実戦で使われてきた憲法を種として植えます。種は価値観だけを語り、規則を語りません。アトリビューションや私的メモリや絵文字のように設定とフックで保証できることは、保証を設置したうえで文面からは消してあります。あなた自身の価値観を書き足し、要らない条文を削るのはあなたの仕事ですが、白紙から始めるのと、議論できる草稿から始めるのは別の仕事です。

## よくある質問

**Q: 全部 CLAUDE.md に書いてはだめですか？**
A: だめではありません。ただし価値観と現状と判断理由を一冊に綴じると、現状が変わるたびに理由が消えるか、理由を守って現状の記述が腐るか、必ずどちらかが起きます。三年もののCLAUDE.mdの中で、今も真実の段落がどれか当てるゲームをしたことがある人は、この分割の理由をすでに体で知っています。

**Q: なぜ CLAUDE.md だけ英語なのですか？**
A: 憲章は毎セッション必ずロードされ、そのトークン代を毎回払うからです。他の文書はプロジェクトの言語で書かれますが、常駐する一枚だけは、最も安く読める言語で書きます。

**Q: adr/ がルートにあるのはなぜですか。docs/adr/ のほうが片付いて見えます。**
A: 片付いて見えるのは、決定の記録を現状説明の子分として扱っているからです。「今どうなっているか」と「なぜそうしたか」は親子ではなく、対等な別の棚です。書庫を書斎の押し入れに入れる蔵はありません。

**Q: 配架が正しければ、中身も正しいですよね？**
A: 別の問題です。全部の宝物が正しい棚にあって、その全部の目録が三年前の現実を語っている蔵は普通に存在します。だから棚の監査と中身の曝涼は別のコマンドです。棚は audit、中身は inspect が受け持ちます。

**Q: Claude が自分でメモを取ってくれる機能は、便利ではないのですか？**
A: 便利です。ただしそのメモは `~/.claude/` の奥、あなたのマシンのあなたのアカウントにだけ書かれます。チームメイトも、半年後の別のマシンのあなたも、それを読めません。次の人が探す場所に書かれなかった知識は、記録ではなく隠匿です。だから蔵は、価値観は憲章へ、規約は docs/ へ、作業の文脈は notes/ へと行き先を示したうえで、私的メモリを閉鎖します。

**Q: 勝手にファイルを動かしませんか？**
A: 動かしません。扉は勅封です。蔵は配架案と点検報告を差し出し、あなたが頷いた分だけ手を入れます。二つの棚に等しく収まりうる宝物や、価値観ともルールとも読める文は、勝手に分類せず、あなたに尋ねます。宝物の意味を決めるのは蔵守の仕事ではないからです。

**Q: 一度整理したら、もう散らからないですよね？**
A: 散らかります。蔵は、使われている限り散らかり続けます。だから曝涼は年中行事なのです。大きな変更のあとに、また audit と inspect を呼んでください。

**Q: 私のプロジェクトは小さくて、五つも棚は要らない気がします。**
A: 正しい感覚です。このルールは「知識があるならここに住む」を定めるもので、棚を埋めるために知識を製造しろとは言いません。二枚のファイルで足りる蔵には、二枚のファイルと、それがどこにあるかの案内板だけで十分です。

**Q: なぜ正倉院ですか？**
A: 一度も焼けたことがなく、千三百年間、収めた物を残し続けている蔵だからです。秘訣は勅封と曝涼、つまり「勝手に開けない」と「定期的に検める」の二つでした。このプラグインがやるのは、その二つの真似です。名前ごと縁起を担ぎました。

## できないこと・正直な制約

- **点検は照合であって、審査ではありません。** 文章の巧拙や設計の良し悪しは判定しません。語彙の検査も直訳の専門用語だけを見て、文体には触れません。間違った推論を正確に記録した ADR は、点検の目には健全な記録です
- **照合できない主張は「照合できない」と報告します。** 実機やリモートの状態を語る文書の真偽は、リポジトリの中からは確かめられません。references/ の標本と実機のずれも、コード側の期待と食い違ったときに間接的に気づけるだけです
- **古びた文書の書き直しは提案までです。** 死んだリンクや改名されたパスは承認のうえ直しますが、消えたアーキテクチャを語るページの再執筆は、書ける知識を持つ人の仕事として報告します。発見を閉じるために中身を発明したら、古い真実が新しい虚構に変わるだけだからです
- **分類は最終的に人間の判断です。** 価値観と現状の境界には、本当に曖昧な宝物が存在します。蔵は基準と推薦を示しますが、票は持ちません
- **静的サイト生成ツールが所有する docs/ には手を出しません。** mkdocs.yml や docusaurus.config が棚の構造を決めている蔵では、発見は報告に留め、動かすかどうかはあなたが決めます
- **メモリ掃除は内部仕様に寄りかかっています。** 私的メモリの置き場所の導出規則は Claude Code の公開仕様ではないため、将来変わると掃除は空振りします。その場合も、消えるべきでない物が消える方向には壊れません。公式設定とフックの二層は公開仕様の上に建っています
- **絵文字の門番は正面玄関しか見ていません。** エスケープ表記で書かれた絵文字や、外部から取得した内容をそのまま保存する経路は検査しません。塞ぐ前に、実際に漏れた例を観測します

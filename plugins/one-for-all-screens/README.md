# one-for-all-screens

> 「端末が増えました。端末ごとに画面を作りますか」
> 「作りません。画面は一枚です」
> 「一枚で、全部の端末に?」
> 「一枚は、全部の端末のために」
> 「では、全部の端末は」
> 「一枚のために。確かめに付き合ってもらいます」

ブラウザで作るゲームの画面を、ウェブのページのように枠に合わせて流し込むと、端末の数だけ別の画面ができます。ある端末で直すと別の端末が崩れ、直す場所は増えていく一方です。

`one-for-all-screens` は、ゲームの画面を基準の大きさ一枚で組み、全体を比率のまま枠に合わせて縮めるプラグインです。一枚の画面が、すべての端末にそれぞれの大きさで届きます。そして、すべての端末が並んで、その一枚が崩れていないかを確かめます。

## 一枚は、全部の端末のために

**基準は一枚だけ。** 基準の大きさは、ノッチやホームバーに隠れない部分の幅と高さです。縦持ちのスマートフォンのゲームなら 390×760 から始めます。

**寸法は一枚の上でだけ測る。** 画面の物はすべて `.stage` の中に、基準の px で置きます。`vw` も `vh` も、枠の大きさで並びを変える `@media` も使いません。入りきらなければ、部品を減らすか並べ替えます。端末ごとに別の一枚を作り始めたら、名前が嘘になります。

**隠れる所には、背景だけを伸ばす。** ノッチとホームバーの分は、同じ倍率で外側に足します。そこまで伸びるのは背景だけです。ボタンと字は置きません。

**字は、自分の箱から出さない。** 長い言葉は箱に収まるようにするか、箱をその言葉が使える広さまで広げます。

## 遅れてくる仲間

アプリの中の WebView は、画面に出た後になってから、ノッチとホームバーの寸法を知らせてきます。知らせたことを告げる合図もありません。一度だけ測る土台では、アプリの中でだけ、違う色の帯が見えたり、ホームバーがボタンに重なったりします。`fit.js` は、寸法が変わるたびに測り直して、遅れてきた仲間も同じ列に並べます。

## 全部の端末は、一枚のために

```
node check.cjs <ゲームのフォルダ> [--ref 390x760] [--desktop] [--eval "<js>"] [--out <フォルダ>]
```

`check.cjs` が、実在するスマートフォンの大きさと寸法、ブラウザの帯で低くなった枠、PC の窓でゲームを開き、一つずつの要素を基準の座標に戻して比べます。1 px を越えて動いた物は `MOVED`、箱から横にはみ出した字は `OVER` として名指しで出し、各枠で並べた画像も書き出します。一台でも崩れていれば、全員でやり直しです。Playwright と Chromium が要ります。

| 種別 | 名前 | 説明 |
|------|------|------|
| Skill | `reference-screen` | 一枚の組み方と確かめ方。画面の土台を作る話や、端末ごとの見え方の話になると Claude が読み込む |
| Template | `template/` | `fit.js`、`stage.css`、`index.html`。ゲームのフォルダに写して使う土台 |
| Script | `check.cjs` | 全部の端末で一枚を確かめる |

## 使い方

ゲームの画面の土台を作る話や、端末ごとの見え方の話を始めると、Claude が読み込みます。`/one-for-all-screens:reference-screen` で呼ぶこともできます。

## よくある質問

**Q: 端末ごとに少しずつ直す方が早くないですか?**
A: 最初の一台は早いです。

**Q: 大きな画面では、もっと多くの物を見せたいのですが。**
A: 見せる物は増えません。同じ一枚が、大きく届きます。増やしたい物があるなら、それは別の一枚です。

**Q: 縦横の比率が違う端末では、余りが出ませんか?**
A: 出ます。余りは背景が引き受けます。ボタンは一歩も外へ出ません。

**Q: 全部で何台と組むんですか?**
A: 数えるたびに、一台増えています。

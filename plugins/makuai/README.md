# makuai

> 「広告は控えめです。1 日に数回だけ」
> 「そのうちの一回が、プレゼンの本番中に出ました」

無料アプリの広告には、収益の話を始める前に決着させるべき問いがひとつあります。最悪の一回はどこで出るのか。平均頻度がどれだけ上品でも、利用者が本来の仕事をしている最中——舞台の上、商談の途中、計測の真っ最中——に出た一回が、評判のすべてを持っていきます。星 1 レビューは平均値ではなく最大値で書かれるからです。

`makuai`(幕間)は、その一回を構造的に消すための原則集です。机上のベストプラクティス集ではなく、実機検証と ADR を重ねて練られた「広告の出しどき・出し方」の判断をプロダクト非依存の原則に書き直した知識スキルで、次の無料版+広告モデルを設計するセッションで Claude が自動的に読み込んで適用します。名前がそのまま中核原則です。広告は幕間にだけ出す。芝居の途中に客席へ売り子は来ません。

## 何が入っているか

原則は四つの関心に分かれています。

**出しどき。** 客前回避の絶対原則。作業中には確率を問わず出さない——「1% なら許される」は原則を 99% 守っている状態ではなく、破っている状態です。出してよい瞬間を作業の区切りとして限定列挙し、判定はすべての広告に先立つ二段ゲートに一箇所集約する。初回セッションは守る。起動時に出すなら、自作モーダルと App Open Ads という二方式の比較から選ぶ。

**頻度。** 誰が広告を止めるのか、という思想の選択。アプリが止める(業界標準の自動 capping)か、利用者が止める(リワード視聴で静寂期間を買う)か。どちらも設計として成立します。大事なのは、選ばなかった方を欠落として扱わないこと——「capping が無い?追加しておきますね」という善意の後任から設計を守るには、持たないこと自体を記録するしかありません。思想を問わず守る下限、停止の単調合成、リワード経済の規律もここに。

**出し方。** 全画面広告の直前に挟む一呼吸の予告画面と、それをプロダクトの世界観の語彙で名付けるという発想。予告があるだけで、広告は奇襲から演出に変わります。ハウス広告にも他社広告と同じ規律(「自社だから多めに」は規律に開く最初の穴です)。App Store Review Guideline 2.5.18 の要件と、一回しか出せない ATT プロンプトの出しどき。

**実装。** 広告 SDK をプロトコル境界の向こうに閉じ、本番設定値の投入だけを最後に置く実装順。乱数・時刻・シーン遷移の注入による決定的テスト。そして「フォアグラウンド復帰」の定義を一箇所間違えると、課金をキャンセルした直後のお客様に全画面広告をお見せするという最悪の接客が完成する、という実地の教訓。

数値(発火確率、停止時間、混合比率)はすべて出典プロダクトの調整結果として例示され、原則とは区別されています。持ち帰るのは構造です。業界定石との照合は 2026 年時点で、AdMob と App Store に固有の事項は本文にその旨を明記してあり、他プラットフォームでは構造だけを移せます。

## 使い方

何もしなくていいです。無料版に広告を入れる設計の話を始めると、Claude がこのスキルを読み込みます。スラッシュコマンドはありません。幕間は呼び出すものではなく、訪れるものだからです。

# makuai

広告で食べていく無料アプリには、越えてはならない線が一本だけあります。利用者が本来の仕事をしている最中に広告を出すこと。舞台の上で、商談の途中で、計測の最中で。その一回が、どれだけ控えめな平均頻度も無意味にします。

`makuai`(幕間)は、出荷済みの iOS アプリで実機検証を重ねて練られた「広告の出しどき・出し方」の判断を、プロダクト非依存の原則に書き直して収めた知識スキルです。次の無料版+広告モデルを設計するセッションで、Claude が自動的に読み込んで適用します。

## 何が入っているか

原則は四つの関心に分かれています。

**出しどき。** 客前回避の絶対原則。広告の害は平均頻度ではなく最悪の一回で決まるから、作業中には確率を問わず出さない。出してよい瞬間を作業の区切りとして限定列挙し、判定はすべての広告に先立つ二段ゲートに一箇所集約する。初回セッションは守る。起動時に出すなら、自作モーダルと App Open Ads という二方式の比較から選ぶ。

**頻度。** 頻度制御には二つの思想があります。業界標準の自動 capping と、クールダウンの役割をリワード視聴へ移譲するユーザー主導方式。どちらも設計として成立し、選ばなかった方を欠落として扱わないために「持たないこと」自体を記録します。思想を問わず守る下限、静寂期間、停止の単調合成、リワード経済の規律もここに。

**出し方。** 全画面広告の直前に挟む約 1 秒の予告画面と、それをプロダクトの世界観の語彙で名付けるという発想。ハウス広告にも他社広告と同じ規律。App Store Review Guideline 2.5.18 の要件と、ATT プロンプトの出しどき。

**実装。** 広告 SDK をプロトコル境界の向こうに閉じ、本番設定値の投入だけを最後に置く実装順。乱数・時刻・シーン遷移の注入による決定的テスト。そして「フォアグラウンド復帰」の定義を誤ると購入キャンセル直後に広告が出る、という実地の教訓。

数値(発火確率、停止時間、混合比率)はすべて出典プロダクトの調整結果として例示され、原則とは区別されています。持ち帰るのは構造です。

## 使い方

何もしなくていいです。無料版に広告を入れる設計の話を始めると、Claude がこのスキルを読み込みます。スラッシュコマンドはありません。これは実行する道具ではなく、設計の前に思い出す原則だからです。

## 出典

iOS アプリ ActTimer の収益化設計(monetization ドキュメントと 11 本の ADR)から、プロダクト固有の判断を剥がして抽出しました。業界定石との照合は 2026 年時点です。AdMob と App Store に固有の事項は本文にその旨を明記してあり、他プラットフォームでは構造だけを移せます。
